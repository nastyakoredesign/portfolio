How one design system serves four brands

I built Centology's design system in Figma. Three white labels run on the same components, with their own colors set by a variable mode.

  • Design system · sole designer
  • Centology (IFS) + 3 white labels
  • Since Dec 2024, ongoing
  • Figma · web portal and client app

TL;DR

One set of components for four brands, switched by a variable mode

  1. Centology's portal also runs under three other brands: LCA, EBC and DMA. Each brand gets its own set of features.
  2. My part: color and type variables, a color mode per brand, components and variants in Figma, and guidelines for developers and AI agents.
  3. In Figma, a screen changes brand with one mode. In code, each brand has its own values for the same color scale, with no semantic layer.

Context and problem

Centology is a portal for UK financial advisers and their clients. Centology also sells it to three firms, LCA, EBC and DMA, who run it under their own brands. Each brand gets its own set of features.

In the old portal, sections had no shared components, and each white label was repainted by hand, so the brands drifted apart. I was the only designer on the redesign, and the product stayed live the whole time.

I started the system on Figma styles and recently moved it to variables. The goal: one set of components for every brand, where a brand brings its own colors instead of a copy of the components.

Constraints

  • Four brands on Centology's components, each using only the part it needs.
  • The only designer on a 13-person team, across the web portal and the client app.
  • Started on Figma styles; moved to variables while the product kept shipping.

My role

What I did

  • Built the color and type variables, with a color mode for each brand.
  • Built 200+ components and variants in Figma, with every state, on those variables.
  • Made the logo one component that switches with the brand mode.
  • Checked each built module against the components and their states.
  • Wrote type, color, icon and status rules for developers and AI agents, and matched the status keys with the developers.

In the old portal, each white label was recolored by hand, so the brands drifted apart.

Components point to one set of names, like Primary/600. Switching the mode changes the value.

Why this way Components refer to a name, not a color. In Figma a mode swaps the values; in code each brand gets its own values for the same names.

Logic Edge cases
Edge cases
  • Brands differ in colors and logo; LCA also has its own font. The logo is one component, in Full and Short sizes, that switches with the same mode.
  • Status colors stay the same in every brand, so a status reads the same everywhere.
  • The names are a scale, like Primary/600, not roles like color/action/primary. The team chose not to add that semantic layer, because moving to it is hard.

Rules a developer or an AI agent can follow

Typography

14 text styles · Typography variables

  1. 01Use Centology text styles — their values come from Typography variables (Font/…); do not recreate typography manually.
  2. 02Select styles by semantic role, not by visual similarity or size alone.
  1. 03Resolve textStyleId and the bound style name; do not infer styles from layer names.
  2. 04Do not apply Centology styles to other white labels.

Centology/Body / Default

Color

Tokens collection · 4 brand modes

  1. 01Use only Centology-scoped styles and variables — never raw HEX values.
  2. 02Resolve colors by token name (e.g. "Primary/600"), not by HEX.
  1. 03Use Entity Status Colors for state indicators — do not invent custom status colors.
  2. 04Do not cross-reference DMA, LCA, or EBC tokens in Centology contexts.

Primary/600, not #3E55FF

Both guidelines If no semantic match exists, report it instead of guessing.

Type, color, icon and lookup rules sit next to the components in Figma. They're written for developers and AI agents working through MCP: never use raw HEX values, and if nothing matches, report it instead of guessing.

Why this way Specific rules can be checked: a color is a variable or a raw value, a status has a key or it doesn't.

Edge cases

From design to code

Empeek's developers build the portal; my part is design and review, not code. They build from my screens and components with every state. Each product runs one brand, so code needs no modes: a brand is its own set of values for the same color scale.
